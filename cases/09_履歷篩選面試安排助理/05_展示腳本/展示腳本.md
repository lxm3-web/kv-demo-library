# 展示腳本 — 09 履歷篩選面試安排助理

> 2026-09-30 改版：原稿偏工程師視角（強調功能齊全），這版改站在「真的做過招募的 HR 主管」角度重寫台詞順序與說法——先解決他們最在意的否決條件（個資／歧視風險），再秀判斷力，最後才是規模化。

## 開場一句
「一個缺收到八份履歷，你們人資是怎麼決定約哪兩個？主管問『為什麼是這兩個』，你答得出來嗎？」

## 先解決疑慮，再秀聰明：個資這關

HR 主管在意的第一件事不是效率，是「會不會惹上麻煩」——這關要先過，後面秀的東西他們才聽得進去。

| 你做 | 它回 | 你說 |
|---|---|---|
| 貼一份沒去識別化的履歷（有姓名電話） | 系統直接退回，請先去識別化再貼 | 「個資這關它自己守，不是靠人資自己記得要小心。」 |

## AI 版（Gem）：判斷要講得出理由

| 你做 | 它回 | 你說 |
|---|---|---|
| 貼 C004（強的） | 逐條對四個必要條件 ✓／✗ 附證據 → 5 分 → 建議面試 → 列出面試要驗證什麼 | 「每一分都有理由，不是印象分——主管問起來，你有東西可以拿出來講。」 |
| 貼 C003（弱的） | 四項都 ✗ → 1 分 → 婉拒 | 「不看年齡、性別、學校，只看條件——這句話不是口號，是系統真的沒有這些欄位可以看。」 |
| 貼 C006（差一項但可補） | 3 分／保留備取，附一句「只缺社群成效數字，補得出來就是 5 分，產業最對口，時段已留」 | 「它不會把人非黑即白地刷掉——這種灰色地帶，才是人資每天真正在判斷的事，不是機器人邏輯。」 |

收尾：「一份一分鐘，講得出理由。但八份要貼八次，時段還是你自己排、信還是你自己寫。」

## Agent 版：規模化，但拍板權還在人資手上

🔴 **操作提醒（避免螢幕變成技術雜訊）**：Agent 版是 Claude Code 真的在終端機裡跑，按下 Enter 之後畫面會滾一堆工具呼叫、思考過程的技術性文字——**這段對 HR 客戶是雜訊，不是賣點**，讓他們一直盯著看只會覺得「這是工程師的東西」，反而跟前面一直強調的「這是懂招募的人做的」互相矛盾。實際操作：

1. 按下 Enter 後，**把終端機視窗切到背景或縮小**，不要讓螢幕停在滾動畫面上
2. 趁它跑的時候，口頭帶一句過渡（例如「它現在在讀履歷、對照條件，這個過程通常要人資一份一份看半小時，它大概十幾秒」），不要冷場乾等，但也不用解說技術細節
3. 跑完之後，**直接切到 outbox 資料夾，用 Excel／瀏覽器打開產出的檔案**——評分總表用 Excel 開、信件用瀏覽器或文字編輯器開，讓客戶看到的是乾淨的表格跟信件，不是程式碼畫面
4. 全程不用打開或展示 `data/`、`workflows/`、`knowledge/` 這些系統內部資料夾，那些是給 Agent 讀的，不是給客戶看的

| 你說／你做 | 它做 | 你說 |
|---|---|---|
| Enter（畫面切到背景，口頭帶過等待） | 8 份全評、分三組（面試／備取／婉拒）、排進面試時段、寫好兩封邀請信、面試題、備取信、婉拒信、主管評核表 | 「它現在在讀履歷、對照條件——人資一份一份看要半小時，它大概十幾秒。」 |
| 切回畫面，直接打開 outbox 的評分總表（用 Excel 開，不要看終端機） | 8 列，每列四項 ✓／✗ 附證據＋一句話理由 | 「同事、主管隨時可以攤開來看，不怕被問『為什麼是他』。」 |
| 開 C006 的備取信 | 除了寄給本人的信，還有一段「只有人資看得到、不會寄出」的內部補充：建議怎麼跟催、時段留了沒 | 「這是真的懂招募的人會做的事——不是幫你決定，是幫你把該做的功課做完。」 |
| 開婉拒信 | 語氣中性、專業、不制式 | 「候選人體驗也是雇主品牌，這封信砸了，比沒收到信更傷——它不會讓被拒的人反過來覺得這家公司很爛。」 |
| `好，發下去` | 八個檔案標已確認；系統提醒「寄信是人資的事」，不會自己按送出 | 「它評、它排、它寫。最後拍板跟按寄出，永遠是你。」 |

收尾：「你們現在花在篩履歷上的時間，多半花在『讀』跟『核對』這兩件苦工上，不是花在『決定』。這套系統把苦工做完，決定權跟責任都還在人資手上。」

## 舊稿備查（2026-09-22 原始版本的重點，供對照）

原稿三個 demo 段落順序是「強的候選人 → 弱的候選人 → 個資防護」，收尾強調「一份一分鐘」「它評它排它寫」的效率面。這版把個資防護提到最前面、加了 C006 灰色地帶案例、收尾從「效率」改成「時間花在苦工上、決定權還是你的」——效率仍然是賣點，但不是 HR 主管第一個想聽到的話。
